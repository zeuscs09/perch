# Wi-Fi bring-up — checklist ที่ต้องทำด้วยมือ

`perchtest` ครอบได้แค่ตรรกะล้วน (การประกอบคำสั่ง การอ่านรายงาน การเรียงรายการ) ส่วนที่เหลือ
ต้องมีบอร์ดจริง วิทยุจริง และเราเตอร์จริง — ไล่ตามลำดับนี้หลังแตะ `ct_wifi.c`, `ct_ble.c`
หรือหน้า Wi-Fi ในแอป

## เตรียม

```bash
cd firmware && idf.py -p /dev/cu.usbserial-XX flash monitor
cd host && ./Scripts/make-app.sh --install     # Bluetooth ใช้ได้เฉพาะจาก .app
```

รอบแรกหลังเปลี่ยน firmware ที่แตะ BLE: macOS ถืออะไรค้างไว้จาก bond เดิม ให้ปล่อยให้
`BLE_GAP_EVENT_REPEAT_PAIRING` จัดการเอง — **อย่า**ไปหาบอร์ดใน System Settings ▸ Bluetooth
เพราะ peripheral ที่เป็น GATT ล้วนไม่โผล่ที่นั่นตั้งแต่แรก

## ไล่ทีละข้อ

1. **บูตแล้วไม่มีอะไรพัง** — `idf.py monitor` ต้องไม่มี `Guru Meditation`, ไม่มี watchdog,
   ไม่มี `E (xxx) wifi:` ซ้ำถี่ · จอต้องขึ้นภาพเหมือนเดิมทุกอย่าง
2. **ไอคอนลิงก์** — มุมขวาบนข้างนาฬิกา: BLE ต่ออยู่ = แท่งไต่ขึ้นสีเขียว · ปิด Bluetooth ที่ Mac
   = เปลี่ยนเป็นขีดจางหรือคลื่นเหลือง (เหลืองเมื่อบอร์ดยังอยู่บนเน็ต) เทียบกับ
   `out/screen_busy.png` และ `out/screen_wifi.png`
3. **เปิดหน้าตั้งค่า** — เมนูบาร์ ▸ เฟือง ▸ Settings… ▸ แท็บ Wi-Fi · รายการต้องเริ่มโผล่ทีละ
   บรรทัดภายในไม่กี่วินาที และสปินเนอร์ต้องหยุดเอง (ไม่ใช่หมุนค้าง = ไม่ได้รับ `ap_end`)
4. **รายการเป็นของบอร์ด ไม่ใช่ของ Mac** — วงที่เป็น 5GHz ล้วนต้อง **ไม่** อยู่ในรายการ
   ถ้าโผล่แปลว่าใครสักคนไปดึงจาก CoreWLAN
5. **จับคู่ตอนกด Connect** — ครั้งแรกที่เขียน config characteristic macOS จะ pair เอง
   (ไม่มีกล่องให้กรอกเลข) · ถ้า log บอร์ดขึ้น `encryption change: 0` แปลว่าเข้ารหัสสำเร็จ
   ค่าอื่นแปลว่าล้ม แล้วคำสั่งจะไม่ถึง firmware เลย
6. **รหัสถูก** — สถานะบนหน้าต่างต้องไป `Connecting…` แล้วเป็น `Connected to <ssid>` พร้อม IP
   ที่ ping จาก Mac ได้จริง (`ping <ip>`) — ping ไม่ผ่านทั้งที่ต่อติด = AP กัน client คุยกัน
   ซึ่งเป็นเน็ตที่ใช้กับ M2 ไม่ได้
7. **รหัสผิด** — พิมพ์ผิดตั้งใจหนึ่งครั้ง: ต้องได้ `wrong password` ไม่ใช่ `not in range`
   และบอร์ดต้องลองใหม่เองเรื่อยๆ โดยจอไม่ค้างและ BLE ไม่หลุด
8. **จำข้ามรีบูต** — ถอดสายจ่ายไฟแล้วเสียบใหม่: บอร์ดต้องกลับขึ้นเน็ตเองโดยไม่ต้องเปิดแอป
9. **ลืมเครือข่าย** — เลือกแถวที่ขึ้นว่า `saved` แล้วกด Forget: ต้องหลุดทันที และหลังรีบูต
   ต้องไม่กลับมาต่อเอง
10. **จำหลายวง** — ตั้งค่าสองเครือข่าย (เช่น เราเตอร์บ้าน + hotspot มือถือ) แล้วปิดตัวที่แรงกว่า
    บอร์ดต้องย้ายไปอีกตัวเองภายในเวลาของ backoff (ไม่เกินหนึ่งนาที)
11. **ทั้งสองวิทยุพร้อมกัน** — ระหว่างที่ต่อ WiFi อยู่ ให้ Claude Code ทำงานจริงสักรอบ:
    มาสคอตต้องขยับตามปกติ ไม่มี snapshot หาย และ log ไม่มี `notify failed`

## ทางเดินที่สอง (LAN)

ข้อ 1–11 ต้องผ่านก่อน ทั้งหมดนี้ต้องมีบอร์ดอยู่บนเน็ตเดียวกับ Mac

12. **กุญแจถูกผลักไปเอง** — ต่อ BLE ครั้งแรกหลังแฟลช: log ของแอป (`Open log`) ต้องมี
    `pushing the lan key to the board (xxxxxxxx)` และ log บอร์ดต้องมี `key set (xxxxxxxx)`
    ด้วยเลขชุดเดียวกัน · ผลักซ้ำทุกครั้งที่เปิดหน้าตั้งค่า = ลายนิ้วมือไม่ตรง ให้ดูว่า
    `ct_lan_key_fingerprint` กับ `LanKey.fingerprint` แฮชของอย่างเดียวกันจริงไหม
13. **ประกาศตัวบน mDNS** — `dns-sd -B _perch._tcp` บน Mac ต้องเห็นชื่อบอร์ด ·
    ไม่เห็นแต่ข้อ 14 ยังผ่านก็ยอมรับได้ (เราเตอร์กรอง multicast) แต่ต้องรู้ตัว
14. **สลับทางจริง** — ปิด Bluetooth ที่ Mac ค้างไว้: ภายใน ~10 วินาที ท้าย popover ต้อง
    เปลี่ยนเป็น `Board connected over Wi-Fi` และจอต้องยัง **สด** (การ์ดกับแผงโควตาไม่หาย
    มาสคอตไม่เป็นสีเทา) ป้ายบนแถบเป็น IP และไอคอนเป็นคลื่น · เร็วกว่า 10 วิ = grace ไม่ทำงาน
15. **หนึ่งเฟรมต่อการเปลี่ยนแปลง ไม่ใช่ต่อวินาที** — ระหว่างอยู่บน LAN ให้ดู log บอร์ด:
    `snapshot ...` ต้องโผล่ตอนสถานะเปลี่ยนหรือนาทีเปลี่ยนเท่านั้น ถ้ามาทุกวินาทีแปลว่า
    การเทียบ "เปลี่ยนไหม" พังอีกรอบ (คีย์ JSON ไม่ได้เรียง)
16. **กลับขึ้น BLE** — เปิด Bluetooth คืน: ท้าย popover กลับเป็น `Board connected` ทันที
    log บอร์ดต้องมี `mac disconnected` (Mac ปล่อยสาย ไม่ใช่ทิ้งค้าง)
17. **ตัวนับข้ามการรีบูตของ Mac** — ระหว่างอยู่บน LAN ให้ปิดแอปแล้วเปิดใหม่: ต้องกลับมา
    ส่งได้เองโดยไม่ต้องแตะ BLE เลย (บอร์ดบอกเลขตัวนับให้ตอนรับสาย) · ถ้าจอค้างและ log
    บอร์ดขึ้น `replayed counter` แปลว่าคำทักทายไม่ได้ถูกอ่าน
18. **ของปลอมเข้าไม่ได้** — `nc <ip> 7333` แล้วพิมพ์อะไรก็ได้: บอร์ดต้องตัดสายทันที
    (`frame did not authenticate` หรือ `frame length ... out of range`) และจอต้องไม่ขยับ
19. **กรอกที่อยู่เอง** — ใส่ IP ลงช่องล่างสุดของแท็บ Wi-Fi แล้วปิด Bluetooth: ต้องต่อได้
    เหมือนเดิมโดยไม่พึ่ง mDNS · ล้างช่องแล้วต้องกลับไปหาเอง
20. **RAM ยังเหลือ** — `idf.py monitor` หลังอยู่บน LAN สักสิบนาที: ไม่มี
    `heap_caps_malloc failed` และไม่มีการรีบูตเอง · DRAM static เหลือ ~24KB เท่านั้น
    (ดู `idf.py size`) ทาง LAN กับ mDNS เป็นสองตัวที่กินเพิ่มล่าสุด

## ที่ที่มักพังก่อนใคร

- **ลิงก์ไม่ผ่านตอนบิลด์** (`iram0_0_seg overflowed`) — สวิตช์ IRAM ใน `sdkconfig.defaults`
  หายไป ดู DESIGN.md หัวข้อ "WiFi"
- **สปินเนอร์หมุนค้าง** — notification หายเพราะไม่ได้ subscribe (`s_event_subscribed`)
  หรือยิงรัวเกินจน NimBLE ทิ้ง ดูหน่วง 20 ms ใน `emit_scan_results`
- **`heap_caps_malloc` คืน NULL ตอนบูต** — WiFi กินก้อนใหญ่ก่อน LVGL ได้บัฟเฟอร์ DMA
  ให้ลดจำนวนบัฟเฟอร์ WiFi ใน `sdkconfig.defaults` ไม่ใช่ลดบัฟเฟอร์วาดจอ
- **ทาง LAN ไม่เคยขึ้นเลยทั้งที่ ping ผ่าน** — macOS 15 ขึ้นไปขออนุญาต Local Network
  แยกต่างหาก ถูกปฏิเสธแล้วทั้ง Bonjour และการต่อไปหา IP ตรงๆ เงียบไปโดยไม่มี error
  ดูที่ System Settings ▸ Privacy & Security ▸ Local Network
- **`the board rejected us — check the key`** ซ้ำๆ — ลายนิ้วมือสองฝั่งไม่ตรง ให้ต่อ BLE
  หนึ่งครั้งแล้วเปิดหน้าตั้งค่า แอปจะผลักกุญแจใหม่ให้เอง (ข้อ 12)
